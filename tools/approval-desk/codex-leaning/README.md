# Codex-leaning Approval Desk

## Platform-native route
Use Codex question cards for Approve / Change / No and free-text questions. Continue discussion in the same chat, naming the card ID. Store the proposal, human decision, discussion and result in the shared Markdown format. Open files and previews beside the chat when helpful.

## Officer workflow
1. Read the project's approval record; assign an officer-prefixed card ID and proposal revision.
2. Present exact proposal, scope and cost using native questions. A question is not approval; keep the card pending.
3. Record the actual human answer and source. Respond in chat, append the exchange under that card, and wait for the human to resolve it.
4. Material changes create a revised proposal and fresh decision. Preserve history.
5. Perform only authorized work; append result evidence separately from approval. Never execute a consumed decision twice.

## Current capability boundary
This edition is native chat plus durable files. The shared browser demo is illustrative and does not save clicks. There is no standalone persistent browser adapter, per-card independent chat creation, automatic reply service or scheduler bundled. A supported scheduled task can be configured separately only when the human requests it.

Start by copying ../shared/APPROVALS_TEMPLATE.md into your project. Test with a fictional no-cost card before live work.
