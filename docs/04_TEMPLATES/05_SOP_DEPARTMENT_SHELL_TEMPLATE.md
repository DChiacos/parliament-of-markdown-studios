# SOP Department Shell Template

## Terms used here

- **SOP:** Standard Operating Procedure, a governed definition of repeatable work.
- **SOT:** Source of Truth, the single controlling source for one governed scope.
- **Reserved shell:** A complete department template with no subject, law, or execution authority.

A Standard Operating Procedure (SOP) shell is reserved architecture, not a procedure. Until an approved distinct subject consumes it, it must state:

> NO SUBJECT | NO PROCEDURAL SOURCE OF TRUTH | NO GOVERNING LAW | NO EXECUTION AUTHORITY

## Folder structure

```text
NN. TBD SOPs/
|-- 00. SOT Declaration/
|   `-- PUBLIC_SOT_TBD_NN_v0.0.0.md
|-- 01. Executive Briefs/
|-- 02. Working Drafts/
|-- 03. Locked Procedures/
|-- 04. Best Practices/
|-- 99. SOP Graveyard/
`-- PUBLIC_SOP_TBD_NN_ReadMe_v0.0.0.md
```

The generic category names are honest runway only. On activation, rename the content categories to subject-specific semantic names derived from real material. Create a Best Practices category only when a qualifying reusable practice exists; do not retain an empty category for symmetry.

## Activation checklist

- [ ] Human authority approved a distinct recurring procedural subject.
- [ ] Existing active procedures and related terms were searched first.
- [ ] Originating evidence and limitations are preserved.
- [ ] `00. SOT Declaration` truthfully identifies candidate authority and recovery.
- [ ] At least three subject-specific semantic content categories exist.
- [ ] Exactly one root ReadMe defines local terms and the cold-reader route.
- [ ] `99. SOP Graveyard` preserves displaced or superseded candidates.
- [ ] All doctrine remains candidate material until explicit human ratification.
- [ ] The next complete reserved shell is created before closure.
